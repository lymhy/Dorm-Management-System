# 员工宿舍管理系统 — 需求规格说明书

> 版本：v1.1 | 日期：2026-09-23 | 状态：与实现对齐
> v1.1 变更：按当前代码（17 个后端模块 / 19 个前端页面 / 15 张表）重写模块清单、字段定义、状态取值、接口清单与权限矩阵；补充 v1.0 未覆盖的在线支付、缴费流水、费用报表、消息通知、用户管理模块；标注尚未实现项。

## 一、系统概述

### 1.1 项目背景
企业/学校为员工提供集中住宿管理，需一套数字化系统管理宿舍楼栋、房间分配、水电费收取、报修处理和访客登记。

### 1.2 用户角色

| 角色 | role 值 | 职责 |
|---|---|---|
| 管理员 (admin) | `admin` | 系统全部数据管理、审批、参数配置、账号管理 |
| 员工 (employee) | `employee` | 查看本人信息/账单，自助报修、访客登记、调宿/退宿申请、在线缴费、接收消息 |

### 1.3 技术栈

| 层级 | 技术 |
|---|---|
| 后端 | Spring Boot 3.4.5 + MyBatis-Plus + Sa-Token（无状态 JWT）+ SpringDoc OpenAPI + BCrypt |
| 前端 | Vue 3 + Vite 5 + Element Plus + Pinia + Vue Router + Axios + ECharts 5 + SheetJS(xlsx) |
| 数据库 | MySQL 8.0（utf8mb4，15 张表） |
| 文档 | Swagger UI (`/doc.html`)、`docs/api.md`、`docs/design.md` |
| 运行环境 | JDK 21、Node 18+、Maven 3.9+ |

### 3.6 水电费管理 `/api/fee`

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT | 主键 |
| room_id | BIGINT | 房间 |
| month | VARCHAR(16) | 账期（2026-09） |
| water_usage | DECIMAL(10,2) | 水用量（m³） |
| elec_usage | DECIMAL(10,2) | 电用量（kWh） |
| water_fee | DECIMAL(10,2) | 水费（元） |
| elec_fee | DECIMAL(10,2) | 电费（元） |
| total | DECIMAL(10,2) | 合计（元，留空时按水费+电费自动补齐） |
| paid | INT | 0 未缴 / 1 已缴 |
| due_date | DATE | 应缴截止日期 |
| remark | VARCHAR(255) | 备注 |

**系统参数：** `water_price` 水价、`elec_price` 电价、`utility_threshold` 预警阈值（默认 200）。

**页面元素：**
- 统计芯片：账单总数 / 已缴 / 未缴 / 未缴金额（`/api/fee/summary`）
- 筛选：关键字（房间号）+ 房间下拉 + 月份 + 缴纳状态；重置
- 多选批量：标记已缴 / 标记未缴 / 批量删除
- 列：房间、月份、水用量、电用量、水费、电费、合计、状态、应缴日期、操作（编辑 / 标记已缴 / 收据 / 删除）
- 弹窗「按用量重算」：读取系统参数自动算费
- 一键催缴：对选中（或全部未缴）账单的房间在住员工发送催缴通知
- 导出 Excel：按当前筛选导出全部（含合计行、未缴合计）
- 员工端：隐藏筛选/批量/新增，只读，保留导出与「在线支付」

**权限：** 管理员全功能；员工只读本人账单。

### 3.10 报修管理 `/api/repair`

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT | 主键 |
| room_id | BIGINT | 报修房间 |
| employee_id | BIGINT | 报修员工 |
| title | VARCHAR(128) | 报修标题 |
| description | VARCHAR(512) | 问题描述 |
| status | INT | 0 待处理 / 1 已接单（处理中） / 2 已完成 |
| handler | VARCHAR(64) | 处理人 |
| handle_remark | VARCHAR(255) | 处理说明 |
| report_time | DATETIME | 报修时间 |
| finish_time | DATETIME | 完成时间 |

**状态流转与通知：** 状态改为 1 → 向报修员工发 `repair_accept` 通知；改为 2 → 发 `repair_finish` 通知。

**提交规则（`POST /api/repair`）：** 员工提交时服务端按登录身份回填 `employee_id`，并强制 `status=0`（待处理）、清空 `handler`/`handle_remark` —— 报修人不由员工填写，处理人与处理说明由管理员分配/处理时填写；`report_time` 为空时由服务端取当前时间。管理员提交不受此约束。

**页面元素：** 状态筛选 + 列表 + 新增/编辑/删除；状态彩色 Tag（待处理-红 / 处理中-橙 / 已完成-绿）；统计待处理/处理中数量。新增/编辑表单中「处理状态/处理人/处理备注」仅管理员可见。

**权限：** 管理员全功能；员工提交（表单仅 房间/标题/描述）+ 查看本人报修（`/api/repair/my`）。

## 四、员工端功能模块

### 4.1 我的概览（仪表盘）
统计卡片：我的房间（楼栋-房号-房型）、待缴费用金额、我的报修数、相关访客数；数据来自 `/api/employee/my-allocation` + `/api/fee/my` + `/api/repair/my` + `/api/visitor/my`。

### 4.2 我的信息（`/api/employee/me`）
展示姓名、工号、部门、性别、手机号、身份证号、入职日期、状态；支持「修改密码」（`PUT /api/auth/password`，校验旧密码，新密码 ≥6 位）。

### 4.3 入住信息（`/api/employee/my-allocation`）
展示当前房间（楼栋/房号/房型/床位）、入住日期、押金、月租；提供「申请调宿」（选择目标房型 + 原因）与「申请退宿」（退宿日期 + 原因）两个入口，提交后进入管理员审批流。

### 4.4 在线缴费（`/api/pay`）
- 「我的账单」列表：月份、水费、电费、合计、状态、应缴日期；未缴行「在线支付」按钮
- 收银台弹窗（`components/PayCashier.vue`）：金额展示 → 「确认支付」→ 成功态；支持取消（关闭订单）；30 分钟超时提示
- 「我的支付订单」列表：订单号、月份、金额、渠道、状态、支付时间；待支付订单可「继续支付」
- 支付成功后账单自动核销，生成缴费流水并收到 `fee_paid` 通知

### 4.5 我的水电费（`/api/fee/my`）
只读账单列表（复用 `Fee.vue`，按角色隐藏筛选/批量/新增），保留导出 Excel 与在线支付入口。

### 4.6 报修（`/api/repair/my`）
提交报修（房间/标题/描述）、查看本人报修进度与状态。报修人取登录身份、初始状态固定为「待处理」，处理人与处理说明由管理员分配时填写，员工不可填写。

### 4.7 访客登记（`/api/visitor/my`）
登记访客（姓名/手机号/受访员工/房间/事由/进入时间）、查看本人相关访客记录。

### 4.8 消息通知（`/api/notification/my`）
- 顶部铃铛 + 未读角标（30s 轮询 `/api/notification/unread-count`）
- 通知列表：类型标签 + 标题 + 内容 + 时间；未读高亮
- 操作：单条标记已读/未读、全部已读、删除；筛选 全部/未读/已读
- 通知类型：`repair_accept` 报修接单 / `repair_finish` 维修完成 / `fee_warning` 水电超限 / `fee_urge` 缴费催缴 / `fee_paid` 缴费成功 / `change_room_result` 换寝审批结果

## 五、数据表设计（15 张）

统一审计字段：`creator / create_time / updater / update_time / deleted（逻辑删除）/ tenant_id`。

| 脚本 | 表 |
|---|---|
| `database/init.sql` | sys_user、building、room、employee、allocation、fee、repair、visitor、announcement、system_config、change_room、move_out |
| `database/notification.sql` | notification（emp_id、type、title、content、biz_id、is_read） |
| `database/fee_payment.sql` | fee_payment（fee_id、room_id、employee_id、amount、month、pay_time、pay_method、operator、remark） |
| `database/payment.sql` | pay_order（order_no 唯一、fee_id、room_id、employee_id、amount、month、channel、status、subject、out_trade_no、paid_time、expire_time、callback_payload、remark） |

**实际 DDL 与 v1.0 文档的差异（已按实际修正）：**
- `announcement.publisher` 为 VARCHAR(64) 姓名，**不是** `publisher_id BIGINT` 外键
- `repair` 无 `images` / `rating` / `handler_remark` / `handle_time` 字段；实际为 `handler` / `handle_remark` / `report_time` / `finish_time`，状态为 0/1/2 三态
- `visitor` 无 `id_card` / `status` 字段；实际为 `visitor_emp_id` + `time_in` / `time_out`
- `fee` 无 `pay_date` 字段（缴费时间记录在 `fee_payment.pay_time`）
- `system_config` 额外包含 `utility_threshold`
- 新增 `notification` / `fee_payment` / `pay_order` 三张表

## 六、接口设计

完整清单见 **`docs/api.md`**（按 17 个模块逐接口列出，含参数与状态机说明）。核心分组：

| 模块 | 前缀 | 主要端点 |
|---|---|---|
| 认证 | `/api/auth` | POST /login、GET /info、PUT /password |
| 仪表盘 | `/api/dashboard` | GET /stats |
| 宿舍楼 / 房间 / 员工 / 入住 | `/api/building` `/api/room` `/api/employee` `/api/allocation` | page / list / {id} / POST / PUT / DELETE |
| 员工自助 | `/api/employee` | GET /me、GET /my-allocation、GET /depts |
| 水电费 | `/api/fee` | page（多条件）、summary、report、my、POST /urge、PUT /{id}/paid、PUT /batch-paid、DELETE /batch |
| 缴费流水 | `/api/fee-payment` | page、by-fee/{feeId}、summary、list、{id}、POST、DELETE |
| 在线支付 | `/api/pay` | POST /order、POST /confirm、POST /close、GET /order/{orderNo}、GET /my、GET /page |
| 报修 / 访客 | `/api/repair` `/api/visitor` | page、my、list、{id}、POST、PUT、DELETE |
| 公告 | `/api/announcement` | page、latest、{id}、POST、PUT、DELETE |
| 调宿 / 退宿 | `/api/change-room` `/api/move-out` | page、POST、PUT /{id}/approve、PUT /{id}/reject |
| 消息通知 | `/api/notification` | my、unread-count、list、read-all、{id}/read、{id}/unread、DELETE |
| 系统参数 | `/api/system-config` | list、GET、PUT |
| 用户管理 | `/api/user` | page、{id}、POST、PUT、DELETE、{id}/reset-password、{id}/status、POST /import |

> 注意：`PUT /api/auth/password` 是修改当前登录用户密码的统一入口（v1.0 文档中的 `/api/employee/password`、`/api/user/password` 均不存在）；员工入住信息为 `GET /api/employee/my-allocation`（非 `/api/allocation/my`）；报修无单独 `dispatch` / `complete` / `rate` 端点，统一走 `PUT /api/repair`。

## 九、非功能性需求

| 维度 | 要求 |
|---|---|
| 性能 | 列表页加载 < 1s，接口响应 < 500ms |
| 并发 | 支持 50 人同时在线 |
| 安全 | Sa-Token 无状态 JWT 认证、密码 BCrypt、按角色控制路由与数据范围 |
| 响应式 | 适配 1024px 以上屏幕（PC 优先） |
| 可维护性 | Controller/Service/Mapper 分层、统一 Result 响应、逻辑删删字段统一 |
| 可扩展性 | 支付通道抽象（`PaymentGateway`），新增微信/支付宝仅需实现接口并注册 Bean |
| 文档 | Swagger UI（/doc.html）+ `docs/api.md` + 本说明书 |

## 十、尚未实现（需求已提出、代码未支持）
